## 2. 已确认选型

| 层次 | 技术 | 用途 |
| --- | --- | --- |
| 前端框架 | Vue 3 | 构建管理界面 |
| 前端语言 | TypeScript | 定义组件、接口和业务数据类型 |
| 前端构建 | Vite | 开发与构建前端项目 |
| UI 组件 | Naive UI | 服务器列表、筛选表单、设置页、弹窗等基础组件 |
| 后端语言 | Go | 实现认证、权限、云接入、实例操作和审计 |
| HTTP 框架 | Gin | 路由、中间件和接口处理 |
| 数据库 | PostgreSQL | 用户、角色、资源授权、云账号配置、操作记录和审计日志 |
| 数据访问 | GORM | 常规业务数据读写 |
| 数据库迁移 | golang-migrate | 显式管理数据库结构变更 |
| 前端路由 | Vue Router | 页面路由与导航 |
| 前端共享状态 | Pinia | 当前用户和必要的跨页面状态 |
| 登录会话 | 服务端 Session + PostgreSQL | 保存会话状态，支持注销与失效处理 |
| OAuth2 客户端 | golang.org/x/oauth2 | 授权码交换和令牌处理 |
| 应用日志 | 标准库 log/slog | 输出结构化运行日志 |
| 后台任务 | Go Worker + PostgreSQL 任务记录 | 默认与 API 同进程启动，支持独立运行；跟踪云操作结果、同步资源和清理到期日志 |
| 监控数据源 | 云监控接口 | 获取 CVM 和 Lighthouse 当前可用指标，不引入采集 Agent |
| 凭证存储 | 应用层加密后存入数据库 | 主密钥通过部署密钥文件注入，首次运行生成并持久保存 |
| 部署 | Linux + Docker Compose + 外置 Nginx | Compose 管理应用服务，外置 Nginx 提供访问入口 |

Naive UI 为已选定的主组件库。具体页面布局、主题配色、信息密度和交互流程在原型设计阶段确定。

## 3. 实现采用的配套依赖

云接入采用前期讨论的官方 SDK 方案，具体依赖版本已锁定在项目依赖文件中。

| 层次 | 推荐技术 | 预期用途 |
| --- | --- | --- |
| 云接入 | 云厂商官方 Go SDK | 首期接入腾讯云 CVM 和 Lighthouse，后续增加阿里云 |

当前构建验证使用 Go 1.26.10、Node.js 22.22.2 和 TypeScript 5.9.3。前端与后端依赖分别由 package-lock.json 和 go.sum 锁定。

## 4. 推荐应用结构

### 4.1 后端模块

采用模块化单体，共用一个后端项目和数据库。建议按业务职责组织以下模块：

| 模块 | 职责 |
| --- | --- |
| 账号与认证 | 管理员创建账号、密码登录、OAuth2 登录和身份关联 |
| 权限 | 用户、角色、功能权限和资源范围校验 |
| 云接入 | 云账号配置、地域配置及云 SDK 调用 |
| 服务器 | 实例查询、搜索筛选和五种单台操作 |
| 监控 | 获取当前指标，处理刷新配置和数据状态 |
| 审计 | 敏感操作记录、结果查询和保留策略 |
| 系统设置 | OAuth2、监控和其他平台配置 |

先实现腾讯云需要的接口和数据结构。增加阿里云时，根据实际差异调整云接入边界，避免提前设计通用插件体系。

首期云接入覆盖 CVM 和 Lighthouse。两者复用服务器列表与业务流程，在 SDK 调用、地域查询、状态和监控指标映射处分别处理。资源标识至少包含云账号、资源类型、地域和实例 ID，授权、任务与审计使用同一套标识。

Lighthouse 关机、重启接口默认使用 `SOFT_FIRST`。适配层执行普通操作时必须显式设置 `StopType=SOFT`，强制操作设置 `StopType=HARD`，避免普通操作失败后自动强制关闭。

### 4.2 前后端交互

建议前后端使用同一域名，后端通过 HTTP JSON 接口提供服务。资源页面进入和重载仅读取快照，缓存有效期 3 分钟，过期仍保留数据；只有手动更新触发同步，后台和页面均不自动回源。页面轮询已触发任务的状态，完成后读取快照。

共享状态仅保存多个页面确实需要的数据。页面查询结果优先由所属页面管理，避免将所有接口数据集中到全局状态中。

### 4.3 后续资源类型扩展

后续可能接入负载均衡（LB）等资源观测。当前技术栈保持不变，首期设计需区分云平台与资源类型，不将所有资源定义为服务器实例。

通用资源标识包含云平台、云账号、资源类型、地域和云端资源 ID，供授权、任务、审计和监控关联使用。名称、标签等通用字段可复用，各资源的专有配置和指标分别定义。

云接入按实际资源类型组织查询和监控代码。服务器启动、关机和重启能力留在服务器模块，未来 LB 观测模块只实现其已确认的查询能力。前端按资源类型提供相应列表和详情，不要求所有资源共用同一套详情字段。

新增资源类型时明确指标名称、单位、维度和可用条件。首期只实现 CVM 与 Lighthouse 所需的结构和流程，不提前引入插件框架、通用指标配置引擎或未使用的资源表。

## 5. 认证与授权

平台登录使用服务端 Session，会话存储于 PostgreSQL。建议通过 HttpOnly Cookie 传递会话标识，涉及写入的请求需有 CSRF 防护。连续无操作 30 分钟失效，单次登录最长 8 小时，时长可配置；注销及账号禁用后的会话撤销流程在接口设计阶段细化。

OAuth2 客户端负责授权流程。用户信息请求、字段映射和第三方身份关联由平台补充实现。第三方身份必须关联管理员创建的已有账号，平台权限由本地账号决定。

支持多个身份提供方，由已登录用户主动绑定，管理员可解绑。第三方身份按提供方和唯一标识关联，禁止按同名或相同邮箱自动关联。

权限采用明确的数据模型，分别保存角色、功能权限和资源范围。每次资源查询与操作都在后端校验。列表查询必须应用资源范围过滤，强制操作必须检查独立权限。

一个用户可拥有多个角色。合并各角色授予的「功能权限与资源范围」组合，不交叉放大权限。预置管理员、只读人员和运维人员，运维人员默认无强制操作权限。首期支持云账号、资源类型、地域和实例范围，暂不支持标签授权。

首期建议直接实现已确定的授权规则。是否引入通用策略引擎，应根据后续实际规则复杂度评估。

## 6. 后台任务与日志

默认通过 `all` 命令在同一进程中运行 HTTP 服务和 Go Worker，也保留 `api`、`worker` 子命令供独立运行。任务记录和操作结果保存在 PostgreSQL 中，服务重启后继续检查未完成任务。

后台任务需要明确领取规则、并发控制、超时与恢复方式。首期暂不增加 Redis 或消息队列；任务吞吐或调度需求超出当前方案后再评估。

对关机、重启等云操作，必须区分提交请求和查询结果。请求超时后可能无法确定云端是否已受理，应先核对云端状态和请求记录，不能盲目重复提交。

操作超时显示「结果待确认」，后台继续核对云端状态。

应用运行日志使用标准库 `log/slog`，与业务审计分别管理。审计记录持久保存到数据库，按配置的保留时间清理。

审计包含登录成功、登录失败，以及敏感变更的成功、失败和拒绝结果。全局默认保留 180 天，可配置；缩短保留时间需提示已有日志将被清理。

## 7. 监控、密钥与部署约束

### 7.1 云监控

监控数据直接来自云监控接口。平台不开发、安装或管理采集 Agent，也不通过 SSH 获取实例内部指标。

监控展示 CPU 和内存使用率、按挂载点统计的磁盘空间使用率、网络入站与出站速率。通过手动更新获取数据，缓存有效期 3 分钟，并显示采样时间。具体指标以云接口可用性为准。

分别验证 CVM 和 Lighthouse 的指标、维度与可用条件。如果云监控接口没有提供某项数据，或实例不满足云端采集条件，页面需明确显示不可用原因。不能以其他指标替代磁盘空间使用率，也不能将无数据展示为零。

### 7.2 凭证与主密钥

云访问凭证等需要还原使用的敏感配置，在应用层加密后存入数据库。用户密码使用单向密码哈希保存，不使用主密钥进行可逆加密。

- 全新部署首次运行时生成主密钥，写入持久化的部署密钥文件，后续启动复用。
- 数据库已有加密数据而密钥文件缺失时，拒绝启动并报告错误，不生成替代密钥。
- 初始化时需避免并发生成或覆盖密钥；API 和 Worker 使用同一份密钥。
- 运行时通过部署密钥文件挂载注入，初始化完成后限制文件访问权限，服务仅读取所需文件。
- 密钥不写入日志、代码仓库或容器镜像；密钥文件须独立备份，与数据库配套恢复。

实现使用 AES-256-GCM。先执行 migrate 创建结构，再执行 init 生成主密钥及初始管理员。密钥路径由 MASTER_KEY_FILE 配置，Compose 挂载为 /run/opsdeck-secrets/master.key；API 和 Worker 只读挂载。恢复时同时恢复数据库和原密钥文件；当前不提供自动密钥轮换。

### 7.3 部署

部署环境为 Linux，使用 Docker Compose 管理应用服务，API 和 Worker 默认合并启动。Nginx 位于 Compose 应用栈之外，由外部环境维护。数据库的数据目录和主密钥文件均需持久保存。

外置 Nginx 负责 HTTPS 和同域反向代理，配置示例见 deploy/nginx.conf.example。前端静态文件包含在应用镜像中，由 API 服务交付。Compose 默认包含 PostgreSQL；也可通过 DATABASE_URL 指向外部数据库。

## 8. 待细化事项

- 腾讯云 CVM 和 Lighthouse 云监控接口的指标可用性，重点验证内存和磁盘空间使用率；保持无 Agent 约束。
- 真实云账号的实例、标签与监控权限，以及不同地域和产品的接口返回。
- 目标 Linux 环境的密钥文件权限、备份恢复和外置 Nginx 域名证书。
- 实际 OAuth2 提供方的授权码、PKCE 和用户信息字段兼容性。
- 大账号下的资源同步时长及 Worker 数量，按实际负载评估。
